# Туториал: выбор объектов мышью и панель Assets — шаг за шагом

В этом туториале мы добавим в редактор две возможности:

1. Кликнуть по объекту в 3D-окне, выбрать его и увидеть рамку выделения.
2. Найти сохранённый объект в панели Assets и перетащить его в сцену.

Будем двигаться небольшими шагами. Сначала научимся определять положение мыши над картинкой, затем выбирать объекты, а после этого займёмся файлами и перетаскиванием. После каждой задачи будет понятно, что должно заработать.

Это учебная версия планов `mouse_picking_selection_plan.md` и `asset_browser_dragdrop_plan.md`. В них можно заглянуть за дополнительными вариантами реализации.

> Примеры кода рассчитаны на версии пакетов проекта: Raylib-cs **8.1.0**, ImGui.NET **1.91.6.1**, rlImgui-cs **3.2.0**. В исходной версии туториала они проверены компиляцией и запуском. Если обновишь пакеты, названия методов и их параметры могут измениться.

## Как читать этот документ

- 🟢 **Простой шаг** — немного кода и готовые методы raylib или ImGui.
- 🟡 **Нужно разобраться** — появятся матрицы или перевод координат.
- 🔴 **На потом** — для первого рабочего результата не понадобится.
- После каждого шага проверяй раздел **«Ожидаемый результат»**. Если он не совпал с тем, что видишь, не добавляй следующий кусок кода: сначала разберись с текущим.
- Для проверки удобно временно выводить значения через `ImGui.Text` прямо в панели.
- Примеры кода — отдельные фрагменты, а не готовые файлы целиком. Подписи перед ними объясняют, куда их добавить и какой предыдущий фрагмент заменить.

### Несколько слов, которые будут встречаться

- **Вьюпорт (3D Viewport)** — панель, в которой видна 3D-сцена.
- **RenderTexture, или RT** — текстура, в которую raylib сначала рисует сцену. Потом ImGui показывает её как обычную картинку во вьюпорте.
- **Пикинг (picking)** — определение объекта под мышью. Проще говоря, выбор объекта кликом.
- **Ассет (asset)** — файл, который редактор использует в проекте: картинка, модель, сцена или сохранённый объект.
- **Префаб (prefab)** — сохранённый шаблон объекта. Из одного шаблона можно создать несколько объектов в сцене.
- **Кадр (frame)** — один проход обновления и отрисовки. Панели ImGui строятся заново каждый кадр.

# Уровень 1. Координаты мыши во вьюпорте 🟢

**Что будем делать.** Нам нужна не просто позиция мыши в окне, а точка на картинке с 3D-сценой.

Представь, что картинка начинается в точке `(200, 100)` окна, а мышь находится в `(250, 130)`. Значит, внутри картинки мышь находится в `(50, 30)`. Но сама текстура может быть больше или меньше картинки на экране, поэтому затем пересчитаем эту точку в пиксели текстуры.

## Задача 1.1. Вывести координаты мыши внутри панели вьюпорта 🟢

**Цель:** узнать, на сколько пикселей мышь смещена от левого верхнего угла картинки.

**Как это работает.** У картинки есть левый верхний угол (`imageMin`) и правый нижний (`imageMax`). Их разность — размер картинки.

Берём положение мыши и вычитаем `imageMin`: `local = mouse - imageMin`. Получаем координаты относительно картинки. Если мышь левее или выше картинки, значение будет отрицательным. Если правее или ниже — больше размера картинки. Так мы проверяем, находится ли курсор внутри.

В примере берём мышь через `ImGui.GetMousePos()`, а границы картинки — через ImGui. Это позволяет считать их в одной системе координат.

**Важно, куда поставить код.** `ImGui.GetItemRectMin()` и `ImGui.GetItemRectMax()` возвращают границы **последнего элемента**. Поэтому вызывай их сразу после `ImageRenderTextureFit`, пока последним элементом остаётся картинка. Если сначала нарисовать текст или кнопку, получишь уже их границы.

**Шаги (в `Inspector.Draw3dViewport`, после вызова `rlImGui.ImageRenderTextureFit`):**

```csharp
var imageMin = ImGui.GetItemRectMin();
var imageMax = ImGui.GetItemRectMax();

var mouse = ImGui.GetMousePos();
var local = new System.Numerics.Vector2(mouse.X - imageMin.X, mouse.Y - imageMin.Y);
var size  = imageMax - imageMin;

bool inside = local.X >= 0 && local.Y >= 0 && local.X <= size.X && local.Y <= size.Y;
ImGui.TextUnformatted(inside ? $"Local: {local.X:F0}, {local.Y:F0}" : "Outside image");
```

**Ожидаемый результат:** внизу панели "3D Viewport" бегают числа при мыши над картинкой, при выходе за картинку — «Outside image».

## Задача 1.2. Пересчитать положение мыши в пиксели текстуры 🟢

**Цель:** получить координату мыши в пикселях самого RT (не картинки в панели).

**Как это работает.** Размер картинки на экране не обязательно совпадает с размером текстуры. Например, текстура шириной 1000 пикселей может показываться в панели шириной 500 пикселей. Тогда 250 пикселей от левого края картинки — это 500 пикселей внутри текстуры.

Считаем в три действия:
1. `uv = local / imageSize` — узнаём, какую часть картинки прошла мышь. `0` — начало, `0.5` — середина, `1` — конец.
2. `rtPixel = uv * rtSize` — умножаем эту долю на размер текстуры.
3. `rtY = rtH - rtY` — переворачиваем отсчёт по вертикали. В этом туториале для построения луча нужна координата Y **от нижнего края**, а мышь считает её от верхнего. Это и называют **Y-флипом**.

Настройка `ResScale` и экраны HiDPI могут менять размер RT. Поэтому нельзя просто использовать координаты картинки без пересчёта.

Доступ к размеру RT: `Editor.ViewTexture.Texture.Width/.Height`.

**Что добавить.** Создай `src/Picking.cs`. Пока в нём будет один метод: он возвращает точку в текстуре или `null`, если мышь вне картинки. Позже добавим сюда выбор объектов.

```csharp
using System.Numerics;
using ImGuiNET;

namespace AlpacaEngine;

public static class Picking
{
    public static Vector2? GetMouseInViewportRT(Vector2 imageMin, Vector2 imageMax)
    {
        var mouse = ImGui.GetMousePos();
        var local = mouse - imageMin;
        var size  = imageMax - imageMin;
        if (local.X < 0 || local.Y < 0 || local.X > size.X || local.Y > size.Y) return null;

        var rtSize   = new Vector2(Editor.ViewTexture.Texture.Width, Editor.ViewTexture.Texture.Height);
        var uv       = local / size;
        var rtPixel  = uv * rtSize;
        rtPixel.Y    = rtSize.Y - rtPixel.Y;      // Y-флип: origin RT — снизу
        return rtPixel;
    }
}
```

В панели сохрани получение `imageMin` и `imageMax` из задачи 1.1. Остальной код проверки мыши и вывода текста замени на:

```csharp
var rtPos = Picking.GetMouseInViewportRT(imageMin, imageMax);
if (rtPos is { } p) ImGui.Text($"RT: {p.X:F0}, {p.Y:F0}   RT size: {Editor.ViewTexture.Texture.Width}x{Editor.ViewTexture.Texture.Height}");
else ImGui.TextUnformatted("Outside image");
```

**Ожидаемый результат:** когда мышь над картинкой, видны координаты `RT`. **У верхнего края Y близко к высоте текстуры, у нижнего — к 0**: это нормально, мы уже перевернули отсчёт. После изменения `ResScale` размер `RT size` меняется, но середина картинки по-прежнему соответствует середине текстуры.

**Если результат не совпал:** проверь формулу `local / size * rtSize`. Здесь `size` — размер показанной картинки, а `rtSize` — размер самой текстуры. Это два разных значения.

# Уровень 2. Луч из камеры и пикинг куба 🟡

## Задача 2.1. Сделать камеру доступной из Inspector 🟢

**Цель:** код выбора объектов должен знать, откуда камера смотрит на сцену.

**Зачем это нужно.** В исходном варианте камера хранится в локальной переменной в `Program.cs`. Из `Inspector.Draw3dViewport` к ней нельзя обратиться напрямую.

Для этого прототипа положим камеру в `Editor.Camera`. Тогда и отрисовка сцены, и выбор объектов будут использовать одну камеру. Отдельный сервис или передачу камеры через параметры можно сделать позже.

**Шаги:**
- `EditorState.cs`: + `public static Camera3D Camera;`
- В `StartEditor` переносим создание: `Editor.Camera = new() { Position = new(5,3,5), ... }`.
- В основном цикле используй `Raylib.UpdateCamera(ref Editor.Camera, CameraMode.Free)` и `Raylib.BeginMode3D(Editor.Camera)` вместо обращений к локальной камере.

**Ожидаемый результат:** всё работает как раньше, но локальная переменная удалена.

## Задача 2.2. Понять «луч из камеры» и выбрать способ 🟢/🟡

**Цель:** получить направление в 3D-сцене, на которое указывает мышь.

**Что такое луч.** Представь лазерную указку: она направлена из камеры через точку картинки под курсором в глубину сцены. Нам нужно узнать, какой объект первым встретится на её пути. Это и есть выбор объекта мышью.

Луч (`Ray`) хранит два значения:
- `Position` — откуда он начинается;
- `Direction` — куда направлен. Это вектор длиной 1: он описывает направление, а не расстояние.

В raylib есть готовый метод `Raylib.GetScreenToWorldRay(Vector2 mousePos, Camera3D cam) → Ray`. Он принимает точку в окне и камеру, а возвращает луч. Старое название `GetMouseRay` в Raylib-cs 8.1.0 ещё есть, но помечено устаревшим. Используем новое.

**Почему нельзя просто вызвать этот метод в любой панели.** Он рассчитывает луч так, будто сцена занимает **всё окно raylib**. У нас же сцена показана в отдельной картинке, рядом с другими панелями.

Например, центр картинки может находиться справа от центра окна. Для пользователя это середина сцены, а для метода — точка справа. В итоге луч пойдёт не туда, куда ты кликнул.

Есть два варианта:

### Вариант A 🟢 — временно показать сцену на всё окно
Самый короткий путь: картинка сцены занимает всё окно raylib, и её размер совпадает с размером RT. Тогда можно передать позицию мыши прямо в `GetScreenToWorldRay`.

Это упрощение для первого опыта, а не универсальное решение. **Увеличить только панель недостаточно:** сама картинка должна совпадать с областью окна, без смещения и полей.

⚠️ В обычной раскладке с Hierarchy, Inspector и Assets это условие не выполняется. Можно временно убрать соседние панели и развернуть вьюпорт, но заголовок панели или отступы всё равно могут мешать точному совпадению. Если не получается добиться совпадения или хочешь оставить обычную раскладку, используй вариант B.

### Вариант B 🟡 — рассчитать луч для нашей текстуры
Этот вариант работает независимо от расположения панелей. Берём координату в RT из задачи 1.2 и строим луч именно для неё.

Внутри метода происходит следующее:
1. Переводим пиксели в диапазон от `-1` до `1`. Это **NDC**: левый край — `X = -1`, центр — `0`, правый край — `1`. По Y нижний край — `-1`, верхний — `1`.
2. Получаем матрицы камеры. **View-матрица** описывает, как мир виден из камеры, а **матрица проекции** — как этот вид превращается в картинку.
3. Обращаем это преобразование: по точке картинки находим две точки в 3D — на ближней и дальней границах видимой области (`near` и `far`).
4. Строим луч от первой точки в направлении второй.

Не обязательно сразу разбираться во всех операциях с матрицами. Главное сейчас — понимать вход метода: пиксель RT с Y от нижнего края, камера и размер RT. На выходе — луч в сцене. Добавь метод в `Picking`.

```csharp
// rtPixel — пиксель RT, Y считается СНИЗУ (флип из задачи 1.2 уже сделан)
public static Ray ScreenPixelToRay(Vector2 rtPixel, Camera3D cam, int rtW, int rtH)
{
    // NDC: [-1..1], x слева-направо, y снизу-вверх
    var ndc = new Vector2(rtPixel.X / rtW * 2f - 1f, rtPixel.Y / rtH * 2f - 1f);

    var view = Raylib.GetCameraMatrix(cam);                                  // view-матрица
    var proj = Raylib.GetCameraProjectionMatrix(ref cam, (float)rtW / rtH); // aspect именно RT, не окна!
    Matrix4x4.Invert(Matrix4x4.Transpose(proj * view), out var invViewProj); // конвенция Raylib-cs 8.1.0

    var n = Vector4.Transform(new Vector4(ndc.X, ndc.Y, -1f, 1f), invViewProj); n /= n.W; // near
    var f = Vector4.Transform(new Vector4(ndc.X, ndc.Y,  1f, 1f), invViewProj); f /= f.W; // far

    var p0 = new Vector3(n.X, n.Y, n.Z);
    var p1 = new Vector3(f.X, f.Y, f.Z);
    return new Ray(p0, Vector3.Normalize(p1 - p0));
}
```

**Почему код записан именно так.** В исходной проверке направление этого луча совпало с `GetScreenToWorldRay`, когда RT и окно были одного размера. При использовании Raylib-cs 8.1.0 важно сохранить несколько деталей:
- `GetCameraProjectionMatrix` принимает камеру через `ref`, а вторым аргументом — отношение ширины к высоте (`aspect`). Передавай именно размер RT, не размер окна.
- Raylib-cs и `System.Numerics` по-разному представляют матрицы. Поэтому здесь используется `Transpose(proj * view)`: `Transpose` меняет местами строки и столбцы. Просто заменить это на `view * proj` нельзя — получится неправильное направление луча.
- `Matrix4x4.Invert(m, out result)` записывает обратную матрицу в `result`. Возвращаемое значение показывает, удалось ли её получить.
- Для преобразования вектора используется `Vector4.Transform(v, M)`. Оператор `*` для такого сочетания типов не определён.

**Смысл математики в одной фразе:** при отрисовке мы переводим 3D-точку в точку картинки, а здесь идём в обратную сторону. Такой обратный перевод называют `unproject`. Деление на `W` в коде — часть этого преобразования, после которой получаем обычные координаты точек.

**Как выбрать:** A — для короткого эксперимента при совпадении картинки и окна. B — для редактора с несколькими панелями. Примеры клика и перетаскивания ниже используют A; если выбрал B, в этих местах получай точку через `GetMouseInViewportRT`, а луч — через `ScreenPixelToRay`. Если точка равна `null`, мышь вне картинки и обрабатывать её не нужно.

## Задача 2.3. Пикинг по AABB — клик выбирает объект 🟢 (Вариант A)

**Цель:** клик по кубу во вьюпорте выделяет его.

**Как определим попадание.** Пока не будем проверять каждую грань объекта. Вместо этого представим, что он лежит в прямоугольной коробке, стороны которой параллельны осям X, Y и Z. Такая коробка называется **AABB**.

`GetRayCollisionBox(ray, box)` проверяет, пересёк ли луч коробку. В результате есть `Hit` — было ли попадание, `Distance` — расстояние до него, `Point` — точка попадания.

Один луч может задеть несколько объектов. Выбираем тот, у которого расстояние меньше: он находится ближе к началу луча.

**Шаги:**

1. AABB в `GameObjects/GameObject.cs`:

```csharp
public virtual BoundingBox GetBoundingBox()
{
    var half = Scale / 2f;
    return new BoundingBox(Position - half, Position + half);
}
```
Здесь `Position` — центр куба, а `Scale / 2` — расстояние от центра до его сторон. Так получаем два противоположных угла коробки. **Поворот `Rotation` этот пример не учитывает**: для куба без поворота достаточно, для повёрнутых объектов понадобится более точная проверка.

2. Пикинг в `Picking.cs`:

```csharp
public static GameObject? PickAtMouse(Ray ray, Scene scene)
{
    GameObject? best = null;
    var bestDist = float.MaxValue;

    foreach (var go in scene.GameObjects)
    {
        var c = Raylib.GetRayCollisionBox(ray, go.GetBoundingBox());
        if (!c.Hit || c.Distance < 0f) continue;
        if (c.Distance < bestDist) { bestDist = c.Distance; best = go; }
    }
    return best;
}
```

3. Обработку клика добавь в `Draw3dViewport` сразу после картинки. `IsItemHovered()` должен проверять именно её, а не отладочный текст, нарисованный позже:

```csharp
// вьюпорт hovered И левый клик И не навигация камерой (Alt)
if (ImGui.IsItemHovered()
    && ImGui.IsMouseClicked(ImGuiMouseButton.Left)
    && !Raylib.IsKeyDown(KeyboardKey.LeftAlt))
{
    // Вариант A: мапим mouse window-pos → ray (RT рисуется во весь окно/панель)
    var ray = Raylib.GetScreenToWorldRay(ImGui.GetMousePos(), Editor.Camera);
    Editor.Selected = Picking.PickAtMouse(ray, Editor.CurrentScene);
}
```

**Зачем проверка Alt.** Когда Alt используется для управления камерой, нажатия мыши не должны одновременно выбирать объекты. Поэтому при зажатом `LeftAlt` пропускаем обработку выбора.

**Ожидаемый результат:** клик по кубу → имя появляется в Inspector (редактируемые поля Position/Scale). Клик мимо — Inspector пустеет. При Alt-движении камеры — пикинг не срабатывает.

**Если не работает:** проверяй по очереди, срабатывает ли клик, куда направлен луч и есть ли попадание в коробку. Выводи `ray.Position` и `ray.Direction` там, где доступен `ray`, а `c.Hit` и `c.Distance` — внутри цикла проверки объектов. Если выбирается объект в стороне от мыши, сначала проверь ограничения варианта A.

## Задача 2.4. Визуальная подсветка выделенного 🟢

**Цель:** видеть, кого выбрали.

**Как это работает.** `Raylib.DrawBoundingBox(box, color)` рисует рёбра коробки вокруг объекта. Это часть 3D-сцены, поэтому рисовать её нужно **между `BeginMode3D` и `EndMode3D`**, там же, где рисуются объекты.

Не добавляй этот вызов в код панели ImGui: панель только показывает готовую картинку сцены. Саму рамку нужно нарисовать в RT до показа картинки.

**Шаги** (Program.cs, внутри `BeginMode3D`, после `foreach go.Render()`):

```csharp
if (Editor.Selected is { } sel)
    Raylib.DrawBoundingBox(sel.GetBoundingBox(), Color.Violet);
```

**Ожидаемый результат:** выделяемый куб (мышью или в Hierarchy) обводится фиолетовой рамкой, снимается при клике мимо.

## Задача 2.5. Выбирать объект в Hierarchy только по клику 🟢

**Цель:** выделение в списке объектов не должно меняться само собой.

**В чём проблема.** ImGui заново рисует список каждый кадр. Если присваивать `Editor.Selected = gameObject` просто при отрисовке строки, объект будет выбираться без участия пользователя. Следующая строка может тут же перезаписать выбор.

Разделим две вещи: рисуем строки каждый кадр, а меняем `Editor.Selected` **только когда пользователь кликнул**. Флаг `Selected` нужен лишь для подсветки уже выбранной строки.

**Шаги:** заменить цикл в `DrawHierarchy()`:

```csharp
foreach (var go in Editor.CurrentScene.GameObjects)
{
    var flags = ImGuiTreeNodeFlags.SpanAvailWidth
              | ImGuiTreeNodeFlags.Leaf
              | (go == Editor.Selected ? ImGuiTreeNodeFlags.Selected : 0);

    if (ImGui.TreeNodeEx($"{go.Name}##{go.Id}", flags))
        ImGui.TreePop();

    if (ImGui.IsItemClicked(ImGuiMouseButton.Left))
        Editor.Selected = go;             // state — только на клике
}
```

**Зачем `##{go.Id}` в названии.** Часть до `##` видна пользователю, а часть после помогает ImGui различать элементы. Даже если два объекта называются «Cube», их строки не перепутаются, потому что у каждого свой `Id`.

**Ожидаемый результат:** клик по строке в Hierarchy выбирает объект и показывает вокруг него фиолетовую рамку в 3D. Выделение сохраняется, пока не выберешь другой объект или не снимешь его кликом мимо.

# Уровень 3. Asset Database 🟡

**Что будем делать.** Редактору нужен список файлов, которые можно использовать: текстур, моделей, сцен и префабов. `AssetDatabase` будет хранить сведения об этих файлах, а панель Assets — показывать их.

Для каждого файла сохраним:
- `RelativePath` — путь относительно папки проекта, например `Prefabs/cube.prefab`;
- `Id` (`Guid`) — уникальный номер файла, по которому редактор сможет его найти;
- `Type` — вид файла: текстура, модель, сцена или префаб.

Пока это просто список в памяти, а не отдельная база данных вроде SQL.

**Важное ограничение:** чтобы `Guid` не менялся после перезапуска, мы будем хранить его в соседнем служебном файле. Если перенести или переименовать только сам ассет, редактор не найдёт этот служебный файл и выдаст новый `Guid`. Переносить их нужно вместе. Автоматическую обработку переименований оставим на потом — см. `asset_browser_dragdrop_plan.md` §7.

## Задача 3.1. Скан директории и список файлов 🟢

**Цель:** панель «Assets» перечисляет файлы проекта, работает Refresh.

**Что добавить.** В `src/AssetDatabase.cs` создай запись об одном файле и класс со списком записей. `Scan` очищает старый список, обходит папку вместе с вложенными папками и записывает найденные пути.

```csharp
// src/AssetDatabase.cs
public sealed class AssetRecord
{
    public Guid Id = Guid.NewGuid();
    public string RelativePath = "";
    public string Type = "Unknown";
}

public sealed class AssetDatabase
{
    public List<AssetRecord> All = new();
    public string Root = "";

    public void Scan(string root)
    {
        Root = root;
        All.Clear();
        foreach (var path in Directory.EnumerateFiles(root, "*.*", SearchOption.AllDirectories))
            All.Add(new AssetRecord { RelativePath = Path.GetRelativePath(root, path) });
    }
}
```

⚠️ **Этот фрагмент показывает обход файлов, но пока не содержит фильтра.** В проекте `Editor.workingDirectory` указывает на корень репозитория: там лежат не только ассеты, но и исходники, документация и результаты сборки.

При доработке `Scan` исключи папки `obj`, `bin`, `.git`. В следующей задаче добавим определение типа по расширению и оставим только поддерживаемые файлы. Для типа `Unknown` служебные файлы создавать не нужно — иначе они появятся рядом с исходниками и документацией.

Добавь поле `Editor.Assets` типа `AssetDatabase` в `EditorState`. В `StartEditor` создай экземпляр и прочитай папку проекта: `Editor.Assets = new(); Editor.Assets.Scan(Editor.workingDirectory);`

Панель (в `Inspector.DrawAssetBrowser`):

```csharp
ImGui.Begin("Assets");
if (ImGui.Button("Refresh")) Editor.Assets.Scan(Editor.workingDirectory);
foreach (var a in Editor.Assets.All)
    ImGui.Selectable(a.RelativePath);
ImGui.End();
```

**Ожидаемый результат:** в панели Assets список файлов проекта, кнопка Refresh перечитывает диск. Добавил файл в папку проекта → Refresh → файл в списке.

## Задача 3.2. Типы и meta-файлы со стабильным Guid 🟢

**Цель:** тип по расширению, Guid стабилен между запусками редактора.

**Зачем это нужно.** Сейчас при каждом сканировании создаётся новая запись с новым `Guid`. Если сцена запомнит ссылку на текстуру по этому номеру, после следующего сканирования ссылка перестанет работать.

Решение: записать номер в маленький файл рядом с ассетом. Например, рядом с `grass.png` появится `grass.png.asset` с содержимым `{"guid": "..."}`. Такой служебный файл будем называть **мета-файлом**.

Если он уже есть — читаем сохранённый номер. Если нет — создаём новый номер и записываем его. Это похоже на постоянный ID записи в базе: повторное чтение не должно выдавать другой ID.

⚠️ **Не включай мета-файлы в список ассетов.** Пропускай `*.asset`, папки `obj/`, `bin/`, `.git/` и неподдерживаемые расширения вроде `.cs` и `.md`. Мета-файл — информация об ассете, а не ещё один ассет.

**Шаги:**

```csharp
static string TypeOf(string ext) => ext switch
{
    ".png" or ".jpg" or ".jpeg" or ".qoi" => "Texture",
    ".prefab"   => "Prefab",
    ".scene"    => "Scene",
    ".obj" or ".gltf" or ".glb" => "Model",
    _ => "Unknown",
};
```

Добавь `TypeOf` в `AssetDatabase`. Затем доработай `Scan`:
1. Пропускай служебные папки и файлы с расширением `.asset`.
2. Определяй тип по расширению через `TypeOf`. Если получилось `Unknown`, пропускай файл.
3. Для оставшихся файлов записывай тип в `AssetRecord.Type`.
4. Вместо случайного `Id` используй результат `GetOrCreateMetaGuid`, передавая полный путь к ассету.

Сам метод чтения или создания номера тоже добавь в `AssetDatabase`:

```csharp
public Guid GetOrCreateMetaGuid(string absolutePath)
{
    var metaPath = absolutePath + ".asset";
    if (File.Exists(metaPath))
    {
        var doc = JsonDocument.Parse(File.ReadAllText(metaPath));
        if (doc.RootElement.TryGetProperty("guid", out var g) &&
            Guid.TryParse(g.GetString(), out var id)) return id;
    }
    var newId = Guid.NewGuid();
    File.WriteAllText(metaPath, $"{{\"guid\": \"{newId}\"}}");
    return newId;
}
```

**Ожидаемый результат:** в папке проекта появились `*.asset`-файлы. Перезапустил редактор → Guid те же (выведи в списке панели первые 8 символов Guid, чтобы проверить глазами: `ImGui.Text($"{a.Id.ToString()[..8]}")` временно).

## Задача 3.3. Превью текстур 🟢

**Цель:** у текстур в файловом списке — мини-картинка.

**Как это работает.** `Raylib.LoadTexture(absolutePath)` загружает картинку с диска в память видеокарты. После этого `rlImGui.ImageSize(texture, w, h)` может показать её в панели.

Загружать картинку каждый кадр не нужно. Сохраним загруженные текстуры в словаре `Thumbs`, где ключ — `Guid` ассета. При первом обращении загрузим картинку, при следующих — возьмём уже загруженную. Это и есть **кэш**.

Для моделей, сцен и префабов этот метод вернёт `null`: картинки для них пока нет.

**Шаги** (в `AssetDatabase`):

```csharp
public Dictionary<Guid, Texture2D> Thumbs = new();

// для не-текстур превью нет — возвращаем null
// (⚠️ пустая `new Texture2D()` с Id=0 в rlImGui.ImageSize нарисуется
// мусорным квадратом, а не «пустым местом»)
public Texture2D? GetOrCreateThumb(AssetRecord r)
{
    if (r.Type != "Texture") return null;
    if (Thumbs.TryGetValue(r.Id, out var t)) return t;
    var full = Path.Combine(Root, r.RelativePath);
    var tex = Raylib.LoadTexture(full);
    Thumbs[r.Id] = tex;
    return tex;
}
```

В панели (плиткой):

```csharp
foreach (var a in Editor.Assets.All)
{
    if (Editor.Assets.GetOrCreateThumb(a) is { } tex)
    {
        rlImGui.ImageSize(tex, 48, 48);
        ImGui.SameLine();
    }
    ImGui.Selectable($"{Path.GetFileName(a.RelativePath)}  [{a.Type}]");
}
```

**Ожидаемый результат:** напротив каждой `.png/.jpg` — мини-картинка, у остальных — просто строка без картинки.

**Не забудь освободить текстуры.** При закрытии редактора вызови `Raylib.UnloadTexture(t)` для каждой записи в `Thumbs`, пока графическое окно ещё открыто. Это освобождает память видеокарты.

В этом простом варианте `Refresh` перечитывает список файлов, но не очищает кэш. Поэтому уже загруженная картинка останется в памяти даже после удаления файла, а изменённая картинка не обновится до перезапуска. Обновление кэша можно добавить позже.

# Уровень 4. Перетаскивание префаба из Assets в сцену 🟢

## Задача 4.1. Начать перетаскивание файла 🟢

**Цель:** «взять» файл из панели Assets мышью.

**Как устроено перетаскивание.** У него есть две стороны:
- **Источник (source)** — строка в Assets, которую пользователь тянет мышью.
- **Приёмник (target)** — картинка вьюпорта, на которую пользователь отпускает файл.

Между ними ImGui передаёт **payload** — небольшой пакет данных. Мы положим в него `Guid` ассета и назовём пакет `"assetId"`. Приёмник с таким же названием сможет его прочитать. Другие типы пакетов он проигнорирует.

Перетаскивание может длиться много кадров. ImGui хранит копию данных, пока пользователь тянет мышь, а мы вызываем методы источника и приёмника при отрисовке панелей. Когда пользователь отпустит кнопку над приёмником, тот обработает данные.

**Почему передаём только `Guid`.** По нему мы найдём запись в `AssetDatabase`. Передавать содержимое файла не нужно — достаточно его номера. Сам `Guid` занимает 16 байт.

**Шаги:** в цикле плиток после `Selectable`:

```csharp
// метод панели должен быть помечен `unsafe` (или вынеси этот блок в отдельный unsafe-метод)
if (ImGui.BeginDragDropSource())
{
    Guid guid = a.Id;
    unsafe { ImGui.SetDragDropPayload("assetId", (IntPtr)(&guid), (uint)sizeof(Guid)); }
    ImGui.TextUnformatted(Path.GetFileName(a.RelativePath));    // что «висит» у курсора
    ImGui.EndDragDropSource();
}
```

**Что здесь необычного для C#.** Метод ImGui принимает адрес данных в памяти, поэтому в примере используются `&guid` и `unsafe`. ImGui сразу копирует эти данные к себе: ему не нужно хранить адрес нашей локальной переменной после вызова.

Для ImGui.NET 1.91.6.1 важно:
- Размер передаётся как `uint`, поэтому в коде есть `(uint)sizeof(Guid)`.
- Для локального `guid` достаточно `&guid` внутри `unsafe`. Добавлять `fixed` не нужно: в этом случае он даст ошибку CS0213.
- В `.csproj` должен быть включён `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>`. В этом проекте он уже включён. Операции с указателями должны находиться в `unsafe`-блоке или методе; в примере передачи есть отдельный блок.

Вариант без `unsafe` тоже возможен — через `Marshal.AllocHGlobal` и `Marshal.StructureToPtr`, но тогда придётся вручную выделять и освобождать память. Для этого шага он сложнее.

**Ожидаемый результат:** зажал плитку, потянул → рядом с мышью «висит» имя файла (это сам ImGui рисует payload-контент). Пока бросить некуда — отпускание отменяет drag.

## Задача 4.2. Принять файл во вьюпорте и найти точку размещения 🟢

**Цель:** после отпускания файла над вьюпортом вывести в консоль точку сцены, куда нужно поставить объект. Сам объект пока не создаём.

**Куда поставить объект.** Точка под мышью задаёт направление, но не расстояние от камеры. Вдоль луча можно поставить объект и близко, и далеко — на картинке он всё равно будет под курсором.

Поэтому договоримся: ставим объект туда, где луч пересекает **плоскость пола `Y = 0`**. Это пока не физическое падение, а просто расчёт позиции.

Любая точка на луче считается так: `p(t) = ray.Position + ray.Direction * t`. Число `t` показывает, насколько далеко мы продвинулись от начала луча. Подставляем условие `p.Y = 0` и получаем:

```
ray.Position.Y + ray.Direction.Y * t = 0
→ t = -ray.Position.Y / ray.Direction.Y     (если Direction.Y != 0)
→ dropPos = ray.Position + ray.Direction * t
```

Если `Direction.Y` почти равен нулю, луч идёт параллельно полу и делить на него нельзя. Если `t` отрицательное, пересечение находится позади начала луча. В примере для этих случаев остаётся запасная позиция `(0, 0, 0)`.

Позже можно ставить объект не на условный пол, а на поверхность другого объекта: искать пересечение с его коробкой или геометрией. Это описано в `asset_browser_dragdrop_plan.md` §4.2.

**Что добавить.** В `Draw3dViewport` сразу после картинки открой блок `BeginDragDropTarget`. Он относится к последнему элементу ImGui, поэтому между картинкой и этим блоком не должно быть другого виджета. Внутри читаем `Guid`, находим ассет и рассчитываем позицию:

```csharp
// метод должен быть помечен `unsafe` (из-за payload.Data)
if (ImGui.BeginDragDropTarget())
{
    var payload = ImGui.AcceptDragDropPayload("assetId");
    if (payload.NativePtr != null)     // НЕ IntPtr.Zero — NativePtr это указатель (сравнение с nint не компилируется, CS0019)
    {
        var guid = Unsafe.AsRef<Guid>(payload.Data);   // System.Runtime.CompilerServices.Unsafe
        var a = Editor.Assets.All.FirstOrDefault(x => x.Id == guid);
        if (a != null)
        {
            // Вариант A: мышь в координатах окна (RT рисуется во весь окно/панель)
            var ray = Raylib.GetScreenToWorldRay(ImGui.GetMousePos(), Editor.Camera);
            var dropPos = Vector3.Zero;
            if (MathF.Abs(ray.Direction.Y) > 0.0001f)
            {
                var t = -ray.Position.Y / ray.Direction.Y;
                if (t > 0) dropPos = ray.Position + ray.Direction * t;
            }
            Console.WriteLine($"Drop '{a.RelativePath}' at {dropPos}");
        }
    }
    ImGui.EndDragDropTarget();         // ВСЕГДА — см. замечание ниже
}
```

**Две важные детали:**
- Если `BeginDragDropTarget()` вернул `true`, в конце этого блока обязательно вызови `EndDragDropTarget()`, даже если пакет ещё не принят. Не переноси `End` внутрь проверки `payload`: иначе нарушится пара открытия и закрытия блока.
- `payload.NativePtr` — указатель. Проверяй его через `!= null`, как в примере. Сравнение с `IntPtr.Zero` здесь не компилируется (CS0019).

⚠️ **Здесь снова используется вариант A:** позицию мыши передаём прямо в `GetScreenToWorldRay`. Если картинка не совпадает со всем окном, замени получение луча на вариант B из задачи 2.2: `Picking.GetMouseInViewportRT(...)` → `ScreenPixelToRay(...)`.

**Ожидаемый результат:** перетаскивая prefab-файл на вьюпорт и бросив — в консоль печатается «Drop 'cube.prefab' at (2, 0, -3)». Двигаешь камеру — точка пересчитывается по-новому. Пока объект не создался — следующий шаг.

## Задача 4.3. Создать объект из префаба 🟢

**Цель:** финал прототипа: бросил объект — он появился в сцене и тут же выбран.

**Что лежит в префабе.** В нашем проекте это JSON с данными одного `GameObject`: названием, позицией, размером и другими полями. Читаем файл и восстанавливаем объект из этих данных.

Атрибуты `[JsonPolymorphic]` и `[JsonDerivedType]` в `GameObjects/GameObject.cs` помогают JSON-сериализатору понять, какой именно объект создавать. Например, значение `$type: simpleCube` обозначает куб.

**Почему нужны `Project.Options`.** Данные `GameObject` объявлены как поля. `System.Text.Json` по умолчанию их не сохраняет и не восстанавливает. В `Project.Options` уже включено `IncludeFields = true`; эти настройки нужно передать в вызов сериализатора. Иначе при сохранении останется только `{"$type":"simpleCube"}`, а при чтении поля получат значения по умолчанию.

**Почему меняем `Id`.** Префаб — шаблон, а каждый созданный из него объект — отдельный экземпляр. Даже если перетащить один префаб дважды, у получившихся объектов должны быть разные `Id`. Это как создание новых записей в базе: нельзя оставлять один и тот же первичный ключ.

**Шаги:**

```csharp
// src/SpawnService.cs
public static class SpawnService
{
    public static GameObject? SpawnFromAsset(AssetRecord asset)
    {
        var full = Path.Combine(Editor.Assets.Root, asset.RelativePath);
        try
        {
            var go = JsonSerializer.Deserialize<GameObject>(File.ReadAllText(full), Project.Options); // Options = IncludeFields!
            if (go == null) return null;

            go.Id = Guid.NewGuid();          // клон — новый Id
            go.ParentId = null;              // и без родителя
            Editor.CurrentScene.GameObjects.Add(go);
            Editor.Selected = go;
            return go;
        }
        catch (Exception e) { Console.WriteLine($"Bad prefab: {e.Message}"); return null; }
    }
}
```

В обработчике отпускания файла из задачи 4.2 замени `Console.WriteLine` на создание объекта. Проверка типа нужна, чтобы не пытаться прочитать текстуру или модель как префаб:

```csharp
if (a.Type == "Prefab")
{
    var go = SpawnService.SpawnFromAsset(a);
    if (go != null) go.Position = dropPos;
}
```

**Ожидаемый результат:** после отпускания `.prefab` во вьюпорте появляется новый куб в рассчитанной точке. Вокруг него видна рамка выделения, а в Inspector доступны его поля. Здесь на `Y = 0` ставится центр объекта; размещение нижней гранью на полу можно добавить отдельно.

### Откуда взять `cube.prefab` для проверки

Самый простой способ — подготовить файл вручную:
1. Проверь вызов `JsonSerializer.Serialize` в `Inspector.DrawTopMenu`, который используется для `Save Project`. Он должен получать `Project.Options`, иначе поля объекта не попадут в файл.
2. Сохрани проект и открой полученный `.scene`.
3. Скопируй JSON **одного куба**, включая `$type` и его поля, в `<workingDirectory>/Prefabs/cube.prefab`. Не копируй всю сцену или массив объектов: метод ожидает один `GameObject`.
4. Нажми Refresh в Assets. Теперь префаб можно перетащить во вьюпорт.

Команду «Save Selected as Prefab» через правый клик в Hierarchy можно добавить позже. Она описана в `asset_browser_dragdrop_plan.md`, задание A5.

# Уровень 5. Полировка (опционально, по желанию)

## 5.1. Показать, куда можно отпустить файл 🟢
Нарисуем рамку вокруг вьюпорта, пока пользователь держит над ним перетаскиваемый ассет.

В ImGui.NET 1.91.6.1 нет метода `ImGui.IsDragDropActive()`. Вместо него внутри блока приёмника из задачи 4.2 используем `AcceptPeekOnly`. Это режим «посмотреть, но не принять»: он позволяет подсветить область ещё до отпускания кнопки. Ниже показано, как дополнить существующий блок, а не создать второй рядом:

```csharp
if (ImGui.BeginDragDropTarget())
{
    // «подсветка» во время пролёта: peek НЕ принимает payload, только проверяет
    var peek = ImGui.AcceptDragDropPayload("assetId", ImGuiDragDropFlags.AcceptPeekOnly);
    if (peek.NativePtr != null)
        ImGui.GetWindowDrawList().AddRect(imageMin, imageMax, 0xFF00FFFF); // жёлтый

    var payload = ImGui.AcceptDragDropPayload("assetId");   // реальный приём — как в 4.2
    // ... обработка drop из задачи 4.2 ...
    ImGui.EndDragDropTarget();
}
```
Число `0xFF00FFFF` задаёт жёлтый цвет. ImGui здесь использует порядок компонентов **ABGR**: прозрачность, синий, зелёный, красный. Поэтому это число не нужно читать как привычное RGB.

**Результат:** во время drag видна рамка «бросай сюда».

## 5.2. Показывать миниатюру рядом с курсором 🟡
Всё, что мы рисуем внутри `BeginDragDropSource()`, ImGui показывает рядом с курсором во время перетаскивания. Поэтому вместо одного имени файла можно показать миниатюру текстуры. Дополняем блок из задачи 4.1:

```csharp
if (ImGui.BeginDragDropSource())
{
    // ... SetDragDropPayload как в 4.1 ...
    if (Editor.Assets.GetOrCreateThumb(a) is { } tex)
        rlImGui.ImageSize(tex, 64, 64);            // «ghost»-превью висит у курсора
    else
        ImGui.TextUnformatted(Path.GetFileName(a.RelativePath));
    ImGui.EndDragDropSource();
}
```
Для текстуры появится картинка, для остальных типов останется имя файла: миниатюры префабов и моделей мы пока не создаём.

Другой способ — рисовать картинку вручную через `ImGui.GetForegroundDrawList().AddImage(...)`. Но тогда придётся самостоятельно отслеживать перетаскивание. Для первого варианта это не нужно. Если позже выберешь ручную отрисовку, в rlImgui-cs 3.2.0 ID текстуры передаётся как `new IntPtr(tex.Id)`; отдельного метода `GetImTextureID` в пакете нет.

**Результат:** при перетаскивании текстуры рядом с курсором видна её миниатюра.

## 5.3. Принимать префабы в Hierarchy 🟢
Можно разрешить отпускать префаб не только на картинку сцены, но и на элемент в Hierarchy. Для этого добавь блок приёмника после выбранного элемента ImGui и используй ту же обработку `assetId`.

Здесь не нужно строить луч: создай объект через `SpawnService` и явно поставь его в `(0, 0, 0)`. Если просто не задавать позицию, останется позиция, записанная в префабе. Новый объект добавится в конец списка `GameObjects`.

**Результат:** объект можно добавить через список, даже если нужная часть 3D-сцены сейчас не видна.

## 5.4. Повышение точности пикинга 🟡
Коробка из задачи 2.3 не учитывает поворот. Для повёрнутого куба или сложной модели её границы могут не совпадать с тем, что видно на экране. Даже правильно рассчитанная AABB остаётся грубой проверкой: луч может попасть в коробку, но пройти мимо самой геометрии.

Когда это начнёт мешать, есть два пути:

- **`Raylib.GetRayCollisionMesh(ray, mesh, transform)`** — проверять попадание в треугольники модели, а не только в коробку. Точнее, но требует больше вычислений.
- **GPU-пикинг (ID pass)** — дополнительно нарисовать объекты в отдельную текстуру, назначив каждому свой цвет-номер. Затем прочитать номер в пикселе под мышью. Для этого нужен отдельный проход отрисовки; подробности — в `mouse_picking_selection_plan.md`, §1.1.

Эти проверки можно совместить: сначала быстро отбросить объекты, в коробки которых луч не попал, а затем проверить геометрию оставшихся.

## 5.5. 🔴 GPU-пикинг (ID pass)
Подробный план — в `mouse_picking_selection_plan.md`, §1.1. Для первого рабочего редактора этот шаг не нужен. Вернись к нему, если простой выбор по коробкам и геометрии перестанет устраивать.
