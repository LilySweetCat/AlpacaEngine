# AlpacaEngine — план и гайд

Цель: свой мини-движок + встроенный браш-редактор + ретро 3D-игра (загадки + стрельба + вождение),
лоу-поли стиль с современным подходом.

---

## Стек (финальный, не менять без причины)

| Слой | Выбор | Версия | Зачем |
|---|---|---|---|
| Язык / рантайм | C# / .NET 10 | — | скелет готов |
| Окно, рендер, ввод, аудио | Raylib-cs | **8.1.0** | биндинги raylib 6.0 |
| UI (редактор И игра) | ImGui.NET | **1.91.6.1** | C#-обёртка Dear ImGui |
| Связка raylib + ImGui | rlImgui-cs | **3.2.0** | бэкенд Dear ImGui поверх raylib |
| Физика, коллизии | JoltPhysicsSharp | **2.22.0** | статик-боксы, персонаж, рейкасты |
| Формат карты | JSON (`System.Text.Json`) | встроен | уровни читаются как текст |

Про версии:

- **Raylib-cs 8.1.0 + rlImgui-cs 3.2.0 — совместимость подтверждена смоук-тестом**
  (окно, докинг, атлас шрифтов, rlgl-батчи, 8.x API не задет). Процедура: шаг 0 ниже.
- Raylib-cs 8.x выбран осознанно: в 7.0.x модельная анимация работала криво (glTF-репорты),
  в 8.0.0 переработана под новую систему анимации raylib 6.0 — а у нас будут анимированные
  противники.
- Пара ImGui.NET + rlImgui-cs ходит вместе, по отдельности не обновлять.
- Отставание ImGui.NET от родного Dear ImGui (1.92.x) — не важно: докинг/таблицы/DragFloat
  стабильны с 2023. Не гоняться за форками (psydack и др.).
- Raylib-CsLo — архивирован, не брать.
- Если rlImgui-cs когда-нибудь сломается на новом Raylib-cs: библиотека — один файл ~800 строк,
  лицензия zlib — **вендорим исходник к себе** и чиним, компилятор покажет строки.

## Структура проекта (один проект, как в Godot)

Один exe: редактор и игра — одно и то же приложение, редакторский слой поднимается,
если нет флага `--game`. Разделение Core/Editor из ранних версий плана отменено;
расцепить обратно можно будет потом, по просьбе, за полчаса механики.

```
AlpacaEngine/                  ← ЕДИНСТВЕННЫЙ exe-проект
├─ AlpacaEngine.csproj          пакеты: Raylib-cs, JoltPhysicsSharp, ImGui.NET, rlImgui-cs
│                               + AllowUnsafeBlocks
├─ Program.cs                   вход: --game level.json → сразу игра (без редакторских панелей)
├─ Engine/                       «работает всегда» = движок
│   ├─ GameObject / Component (компонентная модель)
│   ├─ Components/ (Brush, Trigger, Door, Interactable, Dialog,
│   │               Enemy, Player, Car, Inventory)
│   ├─ Map + MapJson (карта, предметы, флаги, условия/эффекты, рецепты)
│   ├─ PhysicsWorld (Jolt: статик-браши, CharacterVirtual, рейкасты)
│   ├─ RetroPass (текстура 960×540, nearest-апскейл)
│   └─ UI игры (ImGui: HUD, меню, диалоги, инвентарь, крафт)
└─ Editor/                       «только в редакторе»
    ├─ EditorShell (докинг, тулбар, Play/Stop, инспектор)
    └─ FlyCamera, выбор брашей, save/load
```

**Единственное правило слоёв** (заменяет сборочную защиту двух проектов):

> Файлы в `Engine/` никогда не пишут `using AlpacaEngine.Editor;`
> Проверка — grep. Для соло-проекта достаточно.

Игровой UI — весь на ImGui, в полном разрешении, поверх ретро-мира (осознанный стиль:
мир пиксельный, интерфейс современный). Важно: `--game` **всё равно поднимает ImGui**
(HUD/меню/диалоги), просто не создаёт редакторские панели и докинг.

Технические решения одной строкой:

- **Рендер**: forward (штатный raylib). Deferred/Forward+ не нужны: лоу-поли, 1–2 источника
  света, туман, 960×540. Ретро-фишки (PSX-дрожание вершин) — один кастомный шейдер поверх.
- **Частицы**: в raylib системы частиц НЕТ — пишем мини-модуль сами (~50–100 строк:
  `List<Particle>` + позиция/скорость/жизнь/цвет + `DrawBillboard`), на шаге 4.
- **Аудио**: встроено (raudio): `LoadSound`/`PlaySound` (wav/ogg/mp3), для эмбиента —
  `LoadMusicStream`/`PlayMusicStream`/`UpdateMusicStream` в цикле кадра. Хватит на всю игру.
- **Анимация противников**: скелетная на raylib 6.0 (для неё и брали 8.1.0); запасной путь —
  процедурная (покачивание/шаг кодом), легитимно-ретро.

## Словарик (термин — одна строка)

- **JSON** — текстовый формат «имя: значение», читается как код, удобно хранить уровни.
- **Браш** — коробка-блок уровня. У нас всегда AABB: позиция + размер, без поворота.
- **AABB** — axis-aligned bounding box, «коробка без поворота».
- **Рейкаст** — «выстрелить лучом и узнать, во что упёрся». Так работает прицел и клик мышью.
- **Хитскан** — стрельба без полёта пули: попал/не попал решает рейкаст мгновенно.
- **Immediate mode UI** — интерфейс рисуется заново каждый кадр кодом (Dear ImGui).
- **RenderTexture** — «виртуальный экран»: рисуем 3D на маленькую текстуру, растягиваем на окно.
- **Докинг** — окна ImGui можно таскать и склеивать, как в Unity/Blender.
- **Кинематик** — физ-тело, которое двигаешь кодом (машина, дверь), физика его не толкает.
- **GameObject / Component** — модель Unity: объект-пустышка + привинченные компоненты-поведения.
- **Инвентарь** — набор предметов игрока (строковые ID: `stick`, `oil`, `key`...).
- **Флаг** — глобальная булева-память уровня («палка_взята», «дверь_открыта»).
- **Условие/эффект** — «если у игрока есть X / флаг Y → дать предмет / выставить флаг / открыть дверь».
- **Рецепт** — из каких предметов собирается другой (`факел = палка + масло + кремний`).

## Компонентная модель (как в Unity, НЕ ECS)

```csharp
class GameObject {
    public string Name;
    public Vector3 Position;
    public List<Component> Components = new();
}

abstract class Component {
    public GameObject Owner;
    public virtual void Update(float dt) {}
    public virtual void Draw() {}
}
```

## Загадки: предметы, флаги, условия/эффекты (вместо языка скриптов)

Сценарий-эталон: *дверь закрыта → нужен ключ → ключ за тёмной комнатой → чтобы пройти,
нужен факел → факел = палка + масло + кремний → палка у NPC (диалог), масло сливается
из машины, кремний роняет противник.*

Всё это — данные, ни строчки «настоящего скрипта»:

```json
{ "name": "NPC_Старик", "components": [
  { "type": "Dialog", "root": { "text": "Чего надо?", "options": [
    { "text": "Дай палку", "if": { "flagNot": "палка_взята" },
      "do": [ { "give": "stick" }, { "setFlag": "палка_взята" } ] },
    { "text": "Пока" } ] } } ] }

{ "name": "Машина", "components": [
  { "type": "Interactable", "prompt": "Слить масло", "if": { "flagNot": "масло_слито" },
    "do": [ { "give": "oil" }, { "setFlag": "масло_слито" } ] } ] }

{ "name": "Дверь", "components": [ { "type": "Door", "lockedBy": "key" } ] }

{ "name": "Тёмная комната", "components": [
  { "type": "Trigger", "enter": [ { "if": { "hasItem": "torch" },
      "do": [ { "log": "Факел освещает путь" } ] },
    { "do": [ { "damage": 5 } ] } ] } ] }
```

Плюс: `items` с рецептами (`"torch": { "recipe": ["stick", "oil", "flint"] }`),
`"Enemy" { "loot": "flint" }`. Механика одна на всё: **условие (`hasItem`/`flag`) →
эффекты (`give`, `setFlag`, `open`, `damage`)**. Инвентарь/крафт/диалоги — ImGui-панели
(Tab). Опечатки в именах целей — валидировать при загрузке (список имён есть в карте).

**Порог для Roslyn C#-скриптов** (.csx на уровень): если в JSON полезла логика с состоянием
(кодовые замки, последовательности, катсцены) — подключаем `Microsoft.CodeAnalysis.CSharp.Scripting`.
Lua не берём, визуальный скриптинг — «потом», после CSG.

## Пошаговый гайд

Каждый шаг заканчивается критерием «готово». Не переходить дальше, пока не выполнен.

### Шаг 0 — каркас — ПРОДЕЛАН

- [x] Один проект `AlpacaEngine` (sln вычищен от Core/Editor, пакеты стоят)
- [x] Смоук-тест пройден: окно + докинг + демо ImGui + вращающийся куб + InputText/DragFloat
      на связке Raylib-cs 8.1.0 + rlImgui-cs 3.2.0 (крашей нет)
- [ ] **Осталось**: `git init`, первый коммит (`.gitignore` уже лежит)

Текущий `Program.cs` — это и есть смоук-тест; его постепенно превращаем в редакторский каркас.

### Шаг 1 — GameObject'ы и сохранение (1–2 вечера)

1. Папка `Engine/`: `GameObject` + `Component` + `BrushComponent` (коробка + цвет).
2. Рендер: пройтись по списку объектов, `DrawCube` + рамка `DrawCubeWires`.
3. Сохранение/загрузка JSON (Ctrl+S / Ctrl+O).

**Готово, когда:** три коробки, написанные руками в JSON (пол + две стены), рисуются,
сохраняются и загружаются.

### Шаг 2 — редактирование мышью (2–3 вечера)

1. Камера-облёт: WASD + зажатая ПКМ крутит взгляд (как Scene-окно в Unity).
2. Клик по брашу: рейкаст из курсора, сравнение со всеми AABB (алгоритм «slab», ~20 строк).
3. Инспектор ImGui: позиция/размер/цвет (`DragFloat` с шагом 0.25), «добавить бруш»,
   «дублировать», «удалить».

**Готово, когда:** комната с дверным проёмом собрана мышью и клавиатурой, JSON не открывался.

### Шаг 3 — Play-режим и пол (1–2 вечера)

1. Настроить Jolt (из примеров JoltPhysicsSharp: `PhysicsSystem`, temp allocator, потоки).
2. При входе в Play каждый `BrushComponent` создаёт неподвижное физ-тело-коробку.
3. Кнопка Play: скрыть редактор, показать точку/капсулу в позиции спавна.

**Готово, когда:** в Play стоишь в своей комнате и не проваливаешься сквозь пол. Esc — назад.

### Шаг 4 — персонаж, стрельба, частицы (2–3 вечера)

1. Ходьба: `CharacterVirtual` из Jolt (готовый контроллер персонажа; копировать из примеров).
2. Выстрел: рейкаст из камеры через прицел → вспышка, минус HP.
3. `EnemyComponent`: HP, «идёт к игроку», урон при касании, лут (`"loot": "flint"`).
4. Мини-частицы: `List<Particle>` — искры попаданий, дым.

**Готово, когда:** можно убить врага, подобрать лут и умереть; HP виден.

### Шаг 5 — машина (2–3 вечера)

1. Аркадная кинематик-машина: 4 рейкаста вниз (высота колёс), скорость по кнопке,
   руль поворачивает «нос».
2. Вход/выход по E: камера пересаживается.

**Готово, когда:** стабильно катаешься на 60 FPS. Рампы-лесенки из мелких брашей пока норм.

### Шаг 6 — загадки (4–6 вечеров)

1. Инвентарь + `items`/рецепты (ImGui-панель по Tab).
2. Условия/эффекты: `give`, `setFlag`, `open`, `damage`; валидация имён при загрузке.
3. `InteractableComponent` (E → проверить условие → эффекты; масло из машины).
4. `DialogComponent`: дерево в JSON, ImGui-окно диалога (палка у NPC).
5. `TriggerComponent` с условиями (тёмная комната без факела — урон).
6. `DoorComponent` с `lockedBy` (ключ из инвентаря открывает).

**Готово, когда:** весь сценарий-эталон (дверь ← ключ ← факел ← NPC/машина/враг)
играется от начала до конца и описан в JSON уровня, без правок кода.

### Шаг 7 — ретро-картинка (1–2 вечера)

1. `RenderTexture` 960×540: весь 3D-мир рисуем в неё, растягиваем nearest (пиксели резкие).
2. Туман вдалеке + простой плоский свет; опционально PSX-шейдер (дрожание вершин).
3. Игровой UI (ImGui) рисуется ПОВЕРХ, в полном разрешении — не пикселируется.

**Готово, когда:** скриншот выглядит «инди из 2020-х про 90-е», интерфейс читаем.

### Шаг 8 — звук и отдельная игра (пара вечеров)

1. Звуки: `LoadSound`/`PlaySound` (выстрел, попадание, дверь) + эмбиент `MusicStream`.
2. Флаг `--game level.json`: редакторский слой не поднимается, ImGui (HUD/меню) — поднимается.
   Отдельный чистый exe (`AlpacaEngine.Game`) — опция «расцепить потом», по желанию.
3. `dotnet publish -c Release` — отдаёшь папку друзьям.

## Грабли (прочитать, потом перечитать когда сломается)

- В Play-режиме перед обработкой игрового ввода проверять
  `ImGui.GetIO().WantCaptureMouse / WantCaptureKeyboard` — иначе мышь «живёт своей жизнью»
  и в редакторе, и в игре одновременно. Грабля №1 у всех.
- Все вызовы ImGui — строго между `rlImGui.Begin()/End()` внутри `BeginDrawing()/EndDrawing()`.
- Кириллица в ImGui НЕ РИСУЕТСЯ шрифтом по умолчанию (только ASCII). Для русских строк —
  грузить свой шрифт с диапазоном кириллицы через `rlImGui.SetupUserFonts`.
- Во время Play браши не редактировать (просто залочить), иначе физика и картинка разъедутся.
- Физику шагать с клампом `dt` (максимум ~1/30 c), иначе после лага всё взрывается.
- Каждый вечер заканчивать `git commit`. Что-то сломалось — откат.
